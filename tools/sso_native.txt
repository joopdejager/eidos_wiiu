# bitfield order (sdk/bw_sso.h), and GCC then refuses `&s->field` on a
# scalar field of it.  A struct listed here is defined with
# scalar_storage_order("big-endian"), the host order on a big-endian
# target, wherever a game source or header defines it.  Only for structs
# no file and no hardware register lays out: game-internal state, or
# memory the port shares in host order.  One tag per line, then why.
#

# is) is listed as `header <path suffix>`: each #include of it in a game
# source is wrapped in #pragma scalar_storage_order default.
