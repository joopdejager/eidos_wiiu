# tools/armdata_widths.txt -- element widths of ARM9 and overlay data objects
# that neither layout/data_objects.json nor a declaration types (tools/ovlink.py
# reads it for an overlay's data, keeping the entries inside its file).
#
# A big-endian host turns the 16- and 32-bit runs of the image into its own
# order when the image is loaded (sdk/armdata.c, swap_to_host).  The runs
# come from data_objects.json's types and, where it only has bytes (its
# fallback when nothing else showed), from the `extern` declarations of the
# build's sources (tools/armdata.py, declared_swap_runs).  An object that is
# declared as bytes too, and that its consumer reads as wider words, is
# listed here: the name, the width, the bytes it covers (0: the object's
# whole extent), then why.  Width 1 keeps the bytes as they are: an image
# of memory the host holds in the DS's order (OAM).  An entry here wins over
# both.  An object no
# source names (reached only through a pointer) is listed as region:address,
# arm9:0xXXXXXXXX or ovNNN:0xXXXXXXXX (overlays share their windows), where
# a data object of that region starts.

_ArenaTableDs    4  0   the same table for the DS
_MainSaveDesc    4  0   BACKUP_SYSTEM_Create reads it as SaveDataParam (six 32-bit words); declared as the incomplete struct SaveAreaDesc
